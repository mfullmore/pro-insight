# Fixtures — Test Workbook Guide

Four hand-built test workbooks, each generated by its own `build-sheet*.js` script (using [ExcelJS](https://www.npmjs.com/package/exceljs), so every formula's cached value is set explicitly alongside the formula itself — the scripts compute "ground truth" values in plain JS and write both, exactly like Excel does after a real recalculation). None of these are meant to be hand-edited directly — edit the generator script and re-run it instead.

For a realistic, large-scale "everything works cleanly" workbook (no unsupported formulas), see `../../support/enterprise-budget-fy26.xlsx` and its own README instead — these four are smaller, more targeted fidelity/edge-case tests.

---

## `budget-test.xlsx` — baseline fidelity test

**Generator:** `build-sheet.js` · **Used by:** `tests/test-fidelity.js`

A clean, representative department-budget workbook: a `Rates` sheet (overhead rate by department code) plus Engineering/Marketing/Sales sheets, each with 4 line items using `VLOOKUP` against the Rates sheet, and a `Summary` sheet rolling everything up with `SUM`, `IF`, `INDEX`/`MATCH`, and two named ranges (`TotalBudget`, `ApprovedBudget`). No unsupported formulas — this is the "does the basic pipeline work at all" test. **Expect all checks to pass.**

```bash
cd fixtures && node build-sheet.js
npm run test:fidelity   # from the project root — runs this file's checks
```

## `budget-test-2.xlsx` — formula-coverage stress test

**Generator:** `build-sheet-2.js` · **Used by:** `tests/test-fidelity-2.js`

Not a budget workbook — a dedicated `FnTests` sheet exercising a broad spread of formula functions against a small `Data` table (also wrapped in a real Excel Table, `BudgetTable`): `SUMIFS`/`COUNTIFS`/`AVERAGEIF`, `IFERROR`/`ISERROR`, the `ROUND` family, `DATE`/`EOMONTH`/quarter-bucketing, `OFFSET`, `INDIRECT`, a structured table reference (`SUM(BudgetTable[Amount])`), and two deliberately-adversarial cases: an external-workbook reference and a genuine circular reference (own sheet, `CircularTest`).

**Expect 18 passed, 2 failed** — the failures are `INDIRECT` and the structured table reference, both confirmed-unsupported by HyperFormula (see `browser-converter/support/README.md`). The circular reference and external-workbook reference are supposed to fail *loudly* (shown as `#CYCLE!` / `#REF!`) — those checks pass precisely because the tool doesn't silently compute a wrong number for them.

```bash
cd fixtures && node build-sheet-2.js
npm run test:fidelity   # from the project root — runs both this and the baseline test
```

## `budget-test-3.xlsx` — the canonical demo/edge-case workbook

**Generator:** `build-sheet-3.js` · **Used by:** `tools/generate-html.js` (default `SRC_FILE`), and manually throughout live testing of all four platform integrations

The workbook used most often when demoing or manually testing any of the four options end to end (browser converter, Confluence, SharePoint, Office Add-in). Same shape as `budget-test.xlsx` (Rates/Engineering/Marketing/Sales/Summary), but deliberately messier and closer to something a real analyst would write:

- **Marketing has 5 line items** instead of 4 (uneven row counts across departments, to make sure nothing assumes a fixed sheet shape)
- **Marketing's 5th line** (`Regional Ad Buy`) uses `INDIRECT("Rates!B"&MATCH(...))` instead of `VLOOKUP` — a plausible thing a power user actually writes, and one of the two known unsupported patterns
- **The Rates sheet is a real Excel Table** (`RatesTable`), and `Summary!B12` references it via a structured reference (`AVERAGE(RatesTable[Overhead Rate])`) — the other known unsupported pattern

**Expect exactly 2 unsupported formulas flagged**: `Marketing!F6` (INDIRECT) and `Summary!B12` (structured table reference). Both should render with the frozen-value fallback (✱, showing Excel's last-known value) rather than a raw error; anything that depends on either cell should show a live error.

```bash
cd fixtures && node build-sheet-3.js
```

## `budget-test-4.xlsx` — adversarial layout/formatting stress test

**Generator:** `build-sheet-4.js` · **Not currently wired into any automated test** — this one's for manual visual QA of the grid renderer, not formula fidelity.

Pressure-tests things that have nothing to do with formulas:

- A merged title cell (`A1:C1`) sitting above a normal table
- Real Excel number formats — currency (`$#,##0.00`), percent (`0%`/`0.00%`), and date (`m/d/yyyy`) — the only fixture that actually exercises `XLSX.SSF` formatting visibly
- A negative currency value (a refund/correction, on purpose)
- Multiple disjoint tables on one sheet (`MultiTable`: two side-by-side, one stacked below with a blank-row gap)
- A sheet with plain data and zero formulas (`Numbers`)
- A text-only notes sheet with a long wrapping string, to check how the grid handles a cell much wider than usual (`Notes`)
- A genuinely empty sheet (`Empty`) — checks the "this sheet is empty" empty state renders correctly instead of erroring

```bash
cd fixtures && node build-sheet-4.js
```

To use it: run the generator, then open the result through `converter.html` or `tools/generate-html.js` (point `SRC_FILE` at `budget-test-4.xlsx`) and eyeball the rendered grid — there's no automated pass/fail here, just "does this look right."

## Regenerating all four at once

```bash
cd fixtures
node build-sheet.js && node build-sheet-2.js && node build-sheet-3.js && node build-sheet-4.js
```

Each script logs its own "ground truth" expected values to the console as it writes the file — useful for manually spot-checking a fixture without running the full fidelity test suite.
